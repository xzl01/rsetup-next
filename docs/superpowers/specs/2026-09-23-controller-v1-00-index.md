## 3. 已确认需求

| 需求ID | 要求 |
| --- | --- |
| C-ARCH | 单实例、自托管、多用户共享设备池；Rust独立中控，模块化单体 |
| C-WEB | Vite+Vue3；发布静态资源嵌入二进制，运行不依赖Node.js或外部静态目录 |
| C-HTTP | 管理端仅HTTP，不内置HTTPS；板端仍独立加密隧道 |
| C-DATA | MySQL并兼容TiDB；监控只保存最新快照，业务/任务/审计持久化 |
| C-SCALE | 按/22规模规划，容量验收包含1024台同时在线；网段不作为身份或授权 |
| C-AUTH | 本地账号，管理员创建；首次初始化admin密码写日志，首次登录强制修改 |
| C-ACL | 角色/权限点和全部/组/单设备范围绑定，动态并集、无deny；仅管理员授权，设备多组 |
| C-ADMIT | 人工批准不自动分组；全部设备授权覆盖新设备；健康PENDING无总期限 |
| C-LIVE | 审批失联仍清连接但留记录；连接与每条业务流分别Ping/Pong校验 |
| C-TASK | 唯一设备变更为重启，单台/批量一主任务、每目标一子任务 |
| C-CONCUR | 设备间受限并发、子任务内部串行；同设备跨主任务互斥，后来者设备忙不排队 |
| C-RECOVER | 持久化任务恢复核实，断线/超时/中控重启不自动重复执行重启 |
| C-POLL | 中控查询为主，状态目标10s，轮询错峰与过载跳过；板端通知关键事件 |
| C-TIME | 独立NTP；启动最多30s，失败回退系统时间，后台持续有上限指数退避 |
| C-I18N | 英文、简体中文一等支持；继承产品无障碍约束 |

不包含设备配置写入、关机、升级、文件分发、任意命令、多租户、高可用或历史监控曲线。用户/准入/授权等中控管理变更不受“设备操作仅重启”限制。

## 4. 架构边界

```text
HTTP/内嵌页面 → 认证授权 → 管理API → 任务协调器 → 板端加密双流
                              │          │
                              └── 业务数据库
查询调度 → 板端状态/时钟查询 → 内存最新快照 → 授权过滤后页面通知
时间提供者 → NTP参考 / 墙钟回退 + 单调计时
```

接入层不代替用户鉴权；协调器不在中控执行硬件操作；周期采集不产生业务主子任务，多浏览器共享采集结果。连接、流代际、运行计时器和最新遥测在内存；持久事实在数据库。异步结果必须校验当前进程/会话/流代际。

数据库和中控私钥/配置是外部依赖，单二进制仅指程序和静态页面。板端私钥不集中到中控。

## 6. 发布阻断与风险

现有协议仍存在：服务端签名未覆盖影响重连的reason_code；验签失败“立即断开”与“返回拒绝”描述冲突；AEAD验证失败后的连接终止策略不明确。这些须独立安全审查、协议修订及双端测试，**解决前不把本组规格标记为可生产发布**。本稿不擅改签名、KDF或记录层。

无限期审批的明文保活不能认证中控，中间人可伪造挂起提示；必须等最终签名验证后才允许业务。HTTP管理链路无法保护密码/会话免受链路窃听篡改，只适合受控可信网络，不能用CSRF防护替代传输加密。
