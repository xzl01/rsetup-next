# 05 · 时间、调度与运维规格

- `controller-v1 / draft-1`，待审阅；[00总目录](2026-09-23-controller-v1-00-index.md)。
- 时间载荷见[03](2026-09-23-controller-v1-03-device-protocol.md)，任务恢复见[04](2026-09-23-controller-v1-04-task-lifecycle.md)。

## 1. 启动与降级

R-01：读取配置、检查私钥0600权限、连接数据库和迁移；启动独立NTP客户端，30s单调预算可与数据库初始化并行。ready需数据库可用、初始化完成、NTP关卡结束；有效NTP可提前结束，30s只限制NTP引入的等待，不限制整个迁移过程。

关卡结束前不开放管理业务API和板端接入，也不恢复下发任务；启动进度写日志。异步等待不阻塞运行时线程。到期无样本用当时中控墙钟启动并标system_fallback，不能假装已同步。

NTP后续失联不关闭ready，继续有上限退避。数据库失联则ready=503，禁止新的设备变更/审批/授权写入；隧道可保活，无法持久的结果不报可靠成功，恢复后查询补齐。健康探针不是业务操作成功证据。

## 2. NTP生命周期

建议单次请求上限3s；30s总预算包括DNS、多个源及全部尝试。后台失败等待 `1s,2s,4s,…`，实际 `min(60s,base+uniform[0,1s))`，次数无限；成功清计数并转60s定期复验，建议有效期180s。重试/样本年龄全部单调计时。

源列表来自配置，不硬编码公共NTP。空列表视不可用，30s关卡到期回退，并按退避节奏重新读取配置文件获取最新源列表（重读节奏即退避节奏，禁止忙循环）；源列表变更不要求进程重启。样本校验源/请求关联、格式、非LI=3、stratum1..15和往返质量。未认证NTP仅运维参考；NTS可选，不是首版依赖。

不自动调用中控/板端OS校时。建议 `abs(Δwall−Δmonotonic)>1s` 判墙钟跳变，旧偏差失效并限速重采样；来源切换/不连续校正递增clock_epoch并记录事件，不回填改写历史。

| quality | 参考语义 |
| --- | --- |
| ntp_valid | 样本UTC加本机单调经过时间，样本未过期且无跳钟 |
| system_fallback | 无有效样本或跳钟失效，使用当前系统墙钟 |
| stale | 曾有效但已过期，使用当前墙钟，旧偏差仅诊断 |

不确定度随样本老化增加，不能无限延长旧样本。NTP恶意源不能由普通校验完全防御，必须保留安全边界。

## 3. 时间证据

HTTP/数据库的 `TimeEvidence`：

| 字段 | 类型/含义 |
| --- | --- |
| system_wall_utc | Instant，中控原始墙钟 |
| reference_utc | Instant，本次选用的参考 |
| quality | ntp_valid/system_fallback/stale |
| clock_epoch | Id，每次不连续参考变化重新生成 |
| source | string/null，运维来源标识，不含凭据 |
| sample_age_ms | Counter/null，单调样本年龄 |
| offset_ms | 有限number/null，参考减中控墙钟 |
| uncertainty_ms | 非负有限number/null，估算不确定度 |

未知不是0。审计同时保存证据、process_epoch和递增event_seq，不依赖板端墙钟排序；数据库ID仅稳定标识，不宣称跨不可靠时钟有绝对因果全序。

R-02：板端样本保留原始墙钟、boot_id、agent_epoch、sample_seq和clock_epoch；中控另记接收TimeEvidence及单调接收时刻。页面“最近收到”使用中控时间，新鲜度只按单调接收年龄。墙钟回跳不会让旧快照覆盖新值；旧会话/旧序号不得更新缓存。

## 4. 板端时间校验

中控在发送clock.get前记录T1、收到后记录T4；板端载荷提供接收T2、发送T3及同次单调值。四个墙钟时间使用毫秒，计算前确认各端处于同一稳定时钟代际。

`board_minus_controller=((T2-T1)+(T3-T4))/2`，`rtt=(T4-T1)-(T3-T2)`。负RTT、跨代际、boot变化、查询期间跳钟或过大延迟不可用于偏差估计；建议RTT上限2s。误差至少含网络不对称、时间戳精度和中控参考误差，不宣称精确同步。

NTP不可用只显示相对中控偏差，不称板端相对标准UTC误差。大但稳定偏差应报告，不直接当无效样本。两主机monotonic绝对值不可相减；boot_id是启动标识而非时钟。

## 5. 跨重启有效期

运行期TTL/请求/退避/保活均单调计时。任务存创建时间证据、参考绝对截止、原始有效期，不复用旧进程monotonic。

恢复时若创建与当前参考足以可信比较，计算剩余期并重新建立单调期限；能证明过期则expired。无法判断的未下发任务held，由04的核验/取消流程处理，不因本机回跳延长寿命。已下发只能核实，不因重建TTL重发。

## 6. 轮询与资源参数

除已确认10s/30s及既有传输参数，其余为本稿建议默认，需审阅与压测。

| 参数 | 默认 | 边界 |
| --- | --- | --- |
| 在线验收目标 | 1024 | 非已验证容量 |
| 已验签PENDING上限 | 2048 | 健康连接无总审批TTL |
| 未认证连接上限 | 128 | 有初始步超时 |
| 设备隧道TCP总上限 | 4096 | 不含浏览器管理HTTP；含替换过渡，先配额后大缓冲 |
| 身份记录容量 | 8192 | 超限拒新，不自动删吊销 |
| 握手全局/来源速率 | 64/s、8/s | NAT部署可调 |
| 常规状态/板端时钟周期 | 10s、60s | 错峰，过载跳过，不补积压轮次 |
| 普通查询速率 | 160/s、burst32 | 状态保留112/s，其它48/s，可借空闲 |
| 普通查询在途 | 768 | 同设备status最多1项 |
| 全局未决请求 | 4096 | 含心跳，预留所有已建立流本端probe名额 |
| 每端每连接未决 | 1024 | 协议上限，不预分配理论最大容量 |
| 重启并发 | 16 | 下发和等待核实占槽，unknown释放槽但保锁 |
| 重启排队有效期 | 60min | 不为提交时离线设备排队等上线 |
| 重启观察窗口 | 5min | dispatching起算，普通RPC仍5s |
| 在线任务核实查询周期 | 5s | 受全局预算，非独立无限轮询 |
| status过期阈值 | 30s | 单调接收年龄，无样本unknown |
| 管理API body/限速 | body≤1MiB、会话写20/s、端点读50/s | body超限400，速率超限429 |

1024台状态约102.4请求/s，时钟另17.1/s；16个执行任务核实约3.2/s。健康探测独立预算，不能以普通查询饱和阻塞保活。全局4096足以为1024设备两流预留2048本端probe，加普通查询与控制请求余量；额外连接/流超过预算必须限制准入，不能超配。

调度按设备分散相位；高优先级任务核实不能长期饿死周期采集。慢设备上一轮未完跳过下一轮，不累加；浏览器只读缓存。unknown后台核实用同一查询预算且可低频，不占重启并发槽。

## 7. 准入与保活

R-03：健康PENDING不因审批久等驱逐；新连接/公钥记录受限，重连复用记录。资源不足用SERVER_ERROR或认证前拒接，不用永久人工拒绝。锁外等待人工审批，同公钥状态转换短事务串行，旧回调校验代际。

原协议为唯一保活参数来源：审批SERVER_PENDING/PENDING_PONG名义5s、pong10s、客户端静默15s；无总期限。HTTP2连接级和双流应用级15s窗口、运行期连续3窗口失败规则；开流首次健康确认及重开见协议§6.6。所有计时单调，NTP恢复不重置这些期限。

OpenData无业务也建流探测；连接正常不表示dispatcher正常，dispatcher正常不表示重启完成。probe使用原始16B nonce，不套业务Protobuf。单流坏不自动判另一流坏，连接级失败只启动一套重连。

流健康投影值（02的control_health/data_health）由本进程流状态映射：starting为本进程刚启动、或流处于初次建立/首次健康确认、尚无probe结果；healthy为流已建立且最近probe窗口有有效pong、无连续失败窗口；degraded为流已建立但存在1–3个连续失败probe窗口、或正在重开（含重开后首次健康确认）；offline为流未建立（连接未建立、流已关闭或连接级故障待重连）。connection_state为连接级：online表示本进程持有已建立的已认证加密通道，否则offline；连接丢失时两条流均offline，单流坏时仅该流健康变化。

## 8. 保留与容量不足

建议终态任务30天、审计180天；幂等索引至少24h且不早于关联任务清理。held、unknown持锁、待核实记录不自动清理。板端去重日志按03保留，不能用中控清理期限替代板端去重规则。

首版不存完整监控历史。数据库/磁盘空间不足报警，并对无法可靠持久的新变更失败关闭，不静默删未决任务。管理员归档设备不能移除吊销防护。

## 9. 备份与恢复

R-04：备份数据库、中控身份私钥和配置，记版本与可组合恢复点；板端私钥不集中保存，初始化明文日志不属于必要备份。MySQL/TiDB工具分别验证，不假定物理备份互通。

旧备份恢复不同于普通重启：进入受控模式，撤销会话、暂停自动准入/变更调度，核对最近吊销/授权/密码/任务后才解除。管理员可显式放行单个设备只读核实，但不因备份queued状态自动重放任务。

不恢复旧进程/流代际、online或内存快照。冷启动页面等待重新连接采集，10s为正常周期而非恢复保证。中控密钥丢失后换钥需重分发信任，不能绕过板端验签。

备份频率建议每日及高风险管理变更前，恢复演练必须记录实际恢复点与耗时；不把该建议当作已实现RPO/RTO服务承诺。

## 10. 专项验收

- TIME-01：DNS卡住/NTP持续丢包30s后ready，后台无限次但有上限退避，空源无忙循环。
- TIME-02：样本过期、恢复、OS回跳改变质量和epoch但不改既有证据，不延长运行TTL。
- TIME-03：无RTC、1970、跨boot/clock_epoch、大稳定偏差和网络不对称正确标记。
- RUN-01：千台错峰、慢响应、多浏览器、普通查询饱和均有界，probe预算不被挤占。
- OPS-01：DB中断不继续下发新变更，恢复查询补齐；旧备份需受控核实，不复活未知授权或重放重启。
